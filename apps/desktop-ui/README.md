# React Interface

The PyDoctor desktop UI: a React 18 single-page app that renders engine reports
and calls the read-only engine through the native bridge.

## Design

This is a no-bundler React app:

- `index.html` loads React and ReactDOM UMD builds from `vendor/`.
- `app.js` contains the interface using `React.createElement` (no JSX build step).
- `styles.css` is a compact hand-authored dark theme.
- `dist/` is generated by `scripts/build-ui.cmd` and is what the desktop shell
  and the packaged executable load.

Why no bundler: the npm registry and its mirrors could not serve package
tarballs reliably from this environment, so Vite/Tailwind could not be
installed. React 18.3.1 UMD was taken from the `dash` wheel on PyPI, which
vendors the same official React builds.

Tailwind CSS is the intended styling system but its standalone binary is not
reachable either. `styles.css` provides the equivalent utility layer by hand.
When a working npm/Tailwind toolchain is available, the markup can be migrated
to Tailwind without changing behavior.

## Bridge contract

The page calls `window.pywebview.api`:

| Method | Arguments | Returns |
| --- | --- | --- |
| `engine_info` | none | engine metadata report |
| `discover` | `project` | schema 1.1 discovery report |
| `run_report` | `mode, interpreter, project, payload` | the selected report |

Modes: `environment`, `packages`, `notebooks`, `error`, `repair`, `discovery`,
`compare`. `payload` carries the pasted traceback for `error` and the previous
report JSON for `repair`.

When opened in a plain browser without the bridge, the interface shows a
"browser preview" badge and a notice instead of failing silently.

## Build

From the project root:

```powershell
cmd /c scripts\build-ui.cmd
```

This copies `index.html`, `app.js`, `styles.css`, and `vendor/` into `dist/`.

## Boundaries

- No diagnostic logic lives here; every number comes from the Python engine.
- No repair is executed from the interface.
- No network request is made at runtime.
